# 根页面切换规范（本仓库硬约定）

> 起因：v1.0.14 真机上反复出现「根页面切换卡顿」「切页后刷新/位置错误」「内容从右上方打开」。
> 本文把结论固化成规范——服务端代码、评审与后续动效改动都按它执行。
> 日期：2026-10-30；适用范围：`navigation/`、`feature/today`、`feature/schedule`、`feature/profile`、`core/ui`。

## 1. 一句话规范

**切 tab 只做位移。入场只在冷启动首帧播一次，之后一生不播。**

| # | 规矩 | 违反后的现象 |
| --- | --- | --- |
| 1 | 切 tab（含复点、含从二级页返回、含通知/胶囊跳转）**不得**给目的地开任何入场级联 | 整页从右上方展开、读作「刷新了一遍」 |
| 2 | 根页入场闸门**一处持有、三页共读**，且用 `rememberSaveable` 跨 Activity 重建 | 进程内第一次切过去、或重建后再切，照样播 |
| 3 | 页内「定位/复位」副作用必须以**锚点变化**为条件，不能挂在「页面进入组合」上 | 翻到第 10 周切走再切回，位置变回第 9 周 |

## 2. 为什么（两条时间轴打架）

切 tab 已经有一整屏横向位移在表达「这一页进来了」：
`tabSlideEnter` / `tabSlideExit`（`navigation/AppTransitions.kt`），弹簧约 220ms。
分段入场（`StaggerIn` / `cascadeIn`）表达的是「内容按阅读顺序就位」，方向从上往下、跨度 300~700ms。
**同一件事说两遍、两条时间轴不同步**，合成观感就是整页从右上方摊开。

「偶发」的真相：上一版只给课表加了闸门，今日与「我的」仍是**进程内第一次进入时放行一次**——
而「第一次进入」恰好就是第一次切过去。于是**每个进程的头一次切 tab 必然播一次**，之后正常。
用户看到的是「有时候会」，实际是「每次冷启动后的第一次都会」。

### 实测证据（PKG110 / 1080×2376）

| 场景 | 修前 | 修后 |
| --- | --- | --- |
| 冷启动后首次点「今日」220ms | 只剩标题 + 首卡半透明，其余区块 alpha≈0 | 内容全部在位，只有位移 |
| 冷启动后首次点「我的」220ms | 顶部区块先出现、下方空帧 | 内容全部在位 |
| 课表页静置 10s | **606 帧**（≈61fps，NowMarker 呼吸灯逐帧推） | **192 帧**（20Hz 定频采样） |
| 第 10 周切走再切回 | 回到第 9 周 | 仍在第 10 周 |

## 3. 代码落点

### 3.1 闸门：`navigation/RootEntrance.kt`

```kotlin
RootEntrancePolicy.shouldPlay(consumed, route)     // 纯逻辑：冷启动首帧 + 根页路由才 true
RootEntranceGate.played / shouldPlay / markPlayed  // 状态：读不消费，消费单独一步
rememberRootEntranceGate()                         // rememberSaveable 持有，跨重建不重置
```

- **读**（`shouldPlay`）可以发生在组合期，**写**（`markPlayed`）必须发生在 `LaunchedEffect` 里。
  在组合期写状态会让这一帧与下一帧对不上，页面拿到的 `playEntrance` 会当场翻面。
- 路由比的是**叶子路由**（`Routes.TODAY` / `SCHEDULE` / `PROFILE`），不是 tab 图路由——
  `currentDestination` 给的是叶子，拿 `*_TAB` 去比永远不相等（这条踩过）。

### 3.2 三个根页的接法（必须同构）

```kotlin
// AppNavGraph
playEntrance = state.entrance.shouldPlay(Routes.PROFILE),
onEntranceShown = { state.entrance.markPlayed() },

// 页面内
val entranceOnce = remember { playEntrance }        // 冻结本次组合的值
LaunchedEffect(Unit) { if (entranceOnce) onEntranceShown() }
val skip = !entranceOnce                            // 传给 StaggerIn / cascadeIn
```

「冻结」不可省：关闸后入参会变 false，若页面继续照入参走，正在播的那一轮会被中途按停，
留下半透明的半张页面。

### 3.3 页内定位副作用：`feature/schedule/WeekAnchorPolicy.kt`

```kotlin
val anchor = WeekAnchorPolicy.anchorOf(ui.timetable?.id, ui.timetable?.startDate, ui.totalWeeks)
LaunchedEffect(anchor) {
    if (!viewModel.shouldRelocate(anchor)) return@LaunchedEffect   // 锚点没变：一个字节都不动
    pagerState.scrollToPage(WeekAnchorPolicy.targetPage(ui.currentWeek, ui.totalWeeks))
}
```

锚点状态记在 **ViewModel** 而不是 `remember`：切页 / 返回 / 重建都会让页面重新组合，
`remember` 每次都是 null，等于「每次进入都重新定位」——那就是 bug 本身。

### 3.4 常驻重绘：`core/ui/Pulse.kt` + `core/ui/PulseMath.kt`

「现在」呼吸灯不再是 `rememberInfiniteTransition` 的无限动画（它让课表页静置也逐帧重绘），
改成**由经过时间直接算值 + 20Hz 采样**。取值是可重放的纯函数，被重建、被打断都能接上。
新增任何「一直在动」的装饰之前先问一句：它是不是让某一页静置也在产帧？

采样频率为什么是 20Hz 而不是更省电的 15Hz：亮度是 `0.55 + 0.45·(1−cos(2πt/T))/2`，
导数峰值 `0.45·π/T` —— 50ms 一步最大变化约 3.9%，66ms 是 5.2%，后者在暗端已经能读成跳格。

## 4. 验证方法（照抄即可复现）

```bash
# 0) 注意：debug 包的包名带后缀（com.zhijian.schedule.debug），
#    直接 adb 对 com.zhijian.schedule 做 gfxinfo 测的是设备上那个旧 release 包。
PKG=com.zhijian.schedule.debug

# 1) 首次切 tab 不应有入场：冷启动后立刻点今日，220ms 帧内容应在原位
adb shell am force-stop $PKG && adb shell am start -n $PKG/com.zhijian.schedule.MainActivity
adb shell "input tap 140 2200; sleep 0.22; screencap -p /data/local/tmp/a.png"

# 2) 静置产帧：课表页 10 秒应约 190 帧（20Hz 采样），不再是 600+
adb shell "dumpsys gfxinfo $PKG reset; sleep 10; dumpsys gfxinfo $PKG | grep 'Total frames'"

# 3) 周次不被覆盖：横滑到第 10 周 → 切我的 → 切回课表，仍应在第 10 周
```

验收口径：

| 项 | 期望 |
| --- | --- |
| 冷启动首帧 | 当前根页播一次分段入场（唯一的合法入场） |
| 任意一次切 tab | 目标页首帧内容已落位，只有整屏位移 |
| 复点当前 tab | 只回顶 + 弹跳，不播入场 |
| 从二级页返回 | 不播入场（`RevealHost` 反向收回依赖这一点） |
| Activity 重建 | 不重播入场、周次不跳回自然当前周 |

## 6. 反模式清单（评审直接按这条拒绝）

- ✗ 在底栏 `onClick`、通知跳转、胶囊跳转里给目的地「开一次入场」。
  切 tab 的唯一动作是 `navigateToTab()` + `islandCollapse.expand()`。
- ✗ 新增第二个「入场回合号 / epoch」字段。回合号是上一版的产物，语义必然退化成
  「每次进入都播一次」；要区分「播不播」只允许用那一个闸门布尔。
- ✗ 把闸门放回普通 `remember`。Activity 重建会清零，重建后第一次切页又播。
- ✗ 给页面的定位副作用挂「页面重新组合」这类条件，或把锚点存在 `remember` 里。
- ✗ 在组合期调用 `markPlayed()`（或任何写状态后立刻读同一状态的组合逻辑）。
- ✗ 新增逐帧无限动画来装饰根页（会让该页静置也满帧重绘，切页时和整屏滑动抢渲染管线）。

## 7. 已知遗留（不属于本次修复范围，别当成已修）

- **纵向滚动位置仍会回到顶部。** 切 tab 回来，周次保留但页面滚到「上午」。
  本次试过三条路线均未通过真机复验，已全部撤回、不留半成品：
  `rememberSaveable` 持有（恢复时机早于摆位 effect）、ViewModel 持有（popUpTo 路径下会被重建）、
  以及「初值 + 等 maxValue 顶起来再 scrollTo」（`LaunchedEffect(week)` 在重建时不再触发）。
  下次动它之前先确认一件事：`WeekGrid` 的 `rememberScrollState()` 内部是 rememberSaveable，
  它会**先**用自己保存的 0 覆盖任何外部初值——所以真正要改的是「谁拥有这份位置」，
  不是再加一层初值参数。
- 呼吸灯仍有 20Hz 重绘（约 192 帧 / 10s）。要归零只能去掉呼吸效果，属于设计取舍。
- 金属主题下的静置开销（`MetalRuntime.supported` 的调用密度）需要另开一次专项测量。
