# 全国高校教务课表「导入渠道」全景调研

> 调研日期：2026-10-26　｜　对象：纸间课表（Android / Kotlin）多教务导入
> 范围：全国高校教务系统向学生/第三方客户端提供课程数据的**全部渠道**，以及客户端侧可达的**导入方式**。
> 证据分级：**【事实】** 有公开页面/实现/官方口径直接支持｜**【部分证实】** 多校样本或实现存在版本差异｜**【未证实】** 单一来源或推断。
> 数据基准：Sleepy 学校目录 4140 条（2026-10-14）、教育部 2025 年全国高等学校名单、各厂商官网口径。

---

## 0. 一页结论

1. **全国高校 3167 所**（教育部 2025-06-20：普通高校 2919 所，含本科 1365、高职专科 1554；成人高校 248）。**【事实】**
2. **教务课表的数据出口只有两大技术形态**：登录后的 **JSON/XHR 接口**（约三分之二）与 **HTML 表格页面**（约三分之一）。导出文件、移动端 App、统一门户、二维码都是这两种形态的**包装或旁路**，不是第四种数据源。**【事实】**
3. **厂商高度集中**：在 1478 条有协议证据的目录条目中，正方系约 40%、强智系约 21%、青果约 11%、超星约 9%、树维系约 6%、金智约 4%、URP 约 3%、乘方约 3%，其余为单校自建协议。**【事实，口径=目录条目非独立高校数】**
4. **「收录」不等于「能导入」**：WakeUp 官网 1800+、文档 1200+，但其 6.1.06 APK 内置 3,570 条学校记录（22 条通用入口）；星链 2000+；超级课程表商店口径 3618；Sleepy 只有 350 个有实测证据的导入配置（来源行 5,779 条）；拾光 264 校 / 269 个 adapter。任何覆盖率宣传都要先问口径。**【事实/部分证实】**
5. **没有任何单一渠道能覆盖全部学校**。业界一致采用三层漏斗：**协议直连（JSON/HTML）→ 页面注入/通用表格 → 文件/截图/手动兜底**。差别只在谁来写解析、在哪执行。**【事实】**
6. **真正的成本不在「接哪家」，而在「一校一部署」**：同厂商不同学校的路径、字段、验证码、SSO、webvpn 都可能不同；研究生系统普遍独立部署。**【事实】**
7. **可落地优先级**：P0 正方新版 + 强智；P1 青果 + 正方旧版 + URP + 树维 classic；P2 金智 + 超星 + 乘方 + eams5；长尾只做识别 + 通用表格 + 文件/截图兜底。**【建议】**

## 2. 渠道分层模型

「全渠道」应当拆成两层，否则会把「数据出口」和「用户操作」混为一谈：

```
                    ┌─────────────────────────────────────────┐
                    │  A. 教务系统侧：数据出口（供给端）        │
                    │  A1 JSON/XHR 接口                        │
                    │  A2 HTML 表格页面                        │
                    │  A3 教务自带导出（Excel/zip/PDF）         │
                    │  A4 移动端/小程序/企业微信                │
                    │  A5 统一身份认证与门户（SSO/ehall/webvpn）│
                    │  A6 校方开放平台/数据中台                 │
                    │  A7 研究生系统（独立一套）                │
                    │  A8 二维码/ICS/分享链接                   │
                    └───────────────────┬─────────────────────┘
                                        │  取数（登录态内）
                    ┌───────────────────▼─────────────────────┐
                    │  B. 客户端侧：用户可达导入（需求端）      │
                    │  B1 学校列表 + 账号直连                   │
                    │  B2 通用协议 + 自定义 URL                 │
                    │  B3 WebView 登录后页面注入「导入本页」     │
                    │  B4 文件导入（xls/xlsx/csv/ics/json/html/zip）│
                    │  B5 粘贴文本                              │
                    │  B6 AI 截图 / OCR / 拍照                  │
                    │  B7 分享口令 / 二维码                     │
                    │  B8 ICS 日历订阅                          │
                    │  B9 手动录入                              │
                    │  B10 浏览器插件 / 用户脚本                │
                    │  B11 教务导出 → 第三方转换器              │
                    └─────────────────────────────────────────┘
```

关键区分：
- **A 层决定「能不能自动取到」**，A1/A2 是自动化的唯一入口，A3 是半自动，A4/A5 只是入口包装。
- **B 层决定「用户能不能自己完成」**，B4-B9 是覆盖率 100% 的兜底层，但依赖人工。

## 3. A 层：教务系统侧数据出口

### 3.0 口径区分（先看这一行）

本报告的「课程导入」指**学生课表数据进入课表客户端/日历**。若指的是**教务系统内部课程库/教学计划导入**，那是另一组渠道：Excel 模板批量导入、培养方案版本同步、上级平台（教育部/省厅）下发、与排课/选课系统对接、与 LMS/资源平台课程映射——属于教务管理侧，不在本报告范围。两者的共同点是都以「课程代码 + 课程名 + 学分 + 学时 + 开课单位」为最小字段集。

### A1. 登录后 JSON/XHR 接口（覆盖最大、成本最低）

| 厂商 | 常见端点 | 关键参数 | 返回结构 | 难度 |
|---|---|---|---|---|
| 正方新版 | `POST /jwglxt/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151`；**必须配** `POST /kbcx/xskbcx_cxRjc.html` 取节次时间 | `xnm` 学年、`xqm` 学期（3/12）、`kzlx=ck` | `kbList[]`：`kcmc/xm/xqj/jc/zcd/cdmc/xqmc/kch_id/jxbmc`；另有 `xsxx`、`sjkList` | 低-中 |
| 强智（含「智校园」App） | `GET /app.do?method=authUser&xh=&pwd=` → `token`；`GET /app.do?method=getKbcxAzc&xh=&xnxqid=&zc=` | `token` 头 | `kcmc/kcsj/kkzc/jsxm/jsmc/sjbz`（`kcsj=50304` 表示周五 3-4 节） | 低 |
| 新 URP | 课表查询接口 | 学期 | `dateList[0].selectCourseList[]`：`courseName/classDay/classSessions/continuingSession/classWeek`（周次位图）/`attendClassTeacher/campusName/teachingBuildingName/classroomName` | 中 |
| 金智 wisedu | **无统一路径**：南大 `wdkb`、北信科 `kbapp`、深职大 `kcbcxmdl`、北理工 `wdkbby` 各不相同 | `XNXQDM=2024-2025-1` | `datas.<模块>.rows`：`KCM/SKJS/JASMC/SKXQ/…` | 中-高 |
| 超星 | 个人课表走 `queryKbForGrdb`（无参、按会话学期）；`sdpkkbList` 是班级/教师端，**不是个人课表** | 会话 | JSON（字段按校/版本变化） | 高 |
| 树维 JSON | `wengine` / `shuwei` 指纹下的接口 | 校定制 | JSON | 中-高 |
| 树维 eams5 | 三段式：`get-data` → `ws/schedule-table/datum` → `print-data` | 学期 | SPA JSON | 高 |
| 乘方 | `POST /xsgrkbcx!getKbRq.action` | 学期 | JSON/HTML 混合 | 中 |

**共性坑**：
- 学期参数（`xnm/xqm`、`XNXQDM`、`xnxqid`）各校编码不同，不能硬编码；
- 部分学校禁 POST、改字段名、加签名；
- 验证码/滑块只在登录环节，取数环节通常不需要；
- Cookie 会话有效期短，需「进入页面再导入」而不是长期后台同步。

### A2. HTML 表格页面（覆盖剩余大头）

| 厂商 | 常见页面 | DOM 特征 | 难度 |
|---|---|---|---|
| 强智 jsxsd | `GET /jsxsd/xskb/xskb_list.do` | `#kbtable`、`div.kbcontent`、周次行 `[01-02节]`、`kbcontent1` 隐藏重复 | 低 |
| 正方旧版 | `xskbcx.aspx` / `default2.aspx` 后 | `#table1`、`.festival`、`td[id]`、`__VIEWSTATE` | 中 |
| 青果 | `/jwweb/` 课表页 | `星期一…星期日` 表头，单元格 `1-16[01-02]`，合并单元格，列数不定（常见「倒数 7 列」） | 中 |
| 老 URP | `xkaction.do?actionType=6` | 标准「星期 × 节次」表格 | 中 |
| 树维 classic EAMS | `GET /eams/courseTableForStd.action` 取 `ids` + `semester.id`；`POST /eams/courseTableForStd!courseTable.action` | 返回 JS，`new TaskActivity(...)` + `index = x*unitCount + y` | 中-高 |
| 乘方 | `/xsgrkbcx`、`/new/xskb` | HTML/JSON 混合 | 中-高 |

**通用表格解析器必须具备**：表头识别、行首节次、单元格切分（`<hr>/<br>/div/p`）、周次表达式、`rowspan/colspan` 展开、iframe 递归、置信度评分。这套能力可同时覆盖强智/正方旧版/青果/老 URP，是性价比最高的一块。

### A3. 教务自带导出（人工半自动，兜底价值最高）

| 厂商 | 导出路径 | 格式 | 注意 |
|---|---|---|---|
| 正方新版 | 信息查询 → 教学进程查看 → 选学期/个人 → 查询 → 勾选课程 → 导出 | `.zip`（内含 xls） | 已知 bug：一次全选会课程名错乱，需按课程分批导出；考试信息可单独导出 `.xlsx` |
| 青果 | 课表页「打印/导出」 | Excel / PDF / 打印页 | 各校开放程度不同 |
| 强智 | 课表页「打印/导出」 | Excel / HTML | 部分校只给打印 |
| 超星 | 课表页导出 | Excel | 版本差异大 |
| 树维 | 课表页导出/打印 | Excel / PDF | — |

**价值**：不依赖接口稳定性，不受反爬影响；适合做「导入失败 → 引导导出 → 文件解析」的兜底链路。**限制（重要）**：学生端可用率远低于预期——青果、强智的导出按钮多开在教师/管理端；正方「教学进程查看」导出的是**每门课一个 zip**（全选还有课程名错乱的已知 bug），课表打印页才有「输出 EXCEL/PDF」；导出内容通常不含调课。因此 A3 只能做「文件导入兼容层」，不能当同步主链路。

### A4. 移动端 / 小程序 / 企业微信 / 钉钉

- 强智所谓 `qz_app` **不是独立路径**，就是「智校园」App 抓包得到的 `app.do`；青果「喜鹊儿」、金智 ehall 微应用（`/jwapp/sys/<module>/…`）、超星学习通、学校企业微信/小程序课表查询。
- 本质仍是同一后端的 API 或 H5 页面，**不构成独立数据源**；价值在于「移动端接口往往比 PC 端更简单、验证码更少」。
- **注意**：超星学习通的课表与教务排课**可能不同源**，不要拿学习通数据反推教务课表。
- 风险：小程序需要抓包/逆向，且接口随版本变化；企业微信入口需要企业身份。

### A5. 统一身份认证与门户（SSO / ehall / webvpn）

- CAS / OAuth2 / SAML / 学校自建统一认证；金智 ehall、正方门户、康赛门户。
- **影响**：登录必须在 WebView 内由用户完成，客户端无法离线复现；会话过期后需重新走 SSO。
- **webvpn**：大量学校校外访问必须经 `webvpn.xxx.edu.cn`，URL 会被重写，协议识别要先剥离 VPN 壳。
- 这是「账号直连」失败率最高的环节，也是「WebView 登录 + 页面注入」成为业界公共解的原因。

### A6. 校方开放平台 / 数据中台

- 少数学校信息中心提供 API 或数据交换平台，无公开统计。
- 价值：一旦拿到，稳定性最高；但需要校方合作，不适合作为通用产品的主路径。

### A7. 研究生系统（独立一套）

- 博雅平台（北航等）、国科大 SEP、南软 GMIS、强智研究生综合管理平台、各校 `yjs/grs/graduate` 系统。
- 目录中研究生条目 303 条，已实现仅 2 条 → **研究生是覆盖率最低、最容易被忽略的一块**。
- 结论：不要假设本科适配器能直接用于研究生；先按域名/标题识别，再单独适配。

### A8. 二维码 / ICS / 分享链接

- 少数新平台在课表页提供「扫码同步」二维码；部分学校/第三方工具提供 ICS 订阅。
- **证据状态**：校方「扫码同步」目前只见第三方软文，未见学校官方页面证据，属**【未证实】**；ICS 是**输出格式**而非数据源，真正有价值的是「App 支持 ICS/Excel 导入导出」这件事本身。
- 本质是「把已登录页面的数据换一种传输方式」，覆盖率低，作为体验补充即可。

## 4. B 层：客户端侧用户可达导入方式

| 渠道 | 用户路径 | 技术实现 | 覆盖 | 维护成本 | 备注 |
|---|---|---|---|---|---|
| B1 学校列表 + 账号直连 | 选学校 → 输学号密码 → 导入 | 内置适配器 + Cookie 重放 | 取决于已适配学校数 | 高（一校一适配） | 体验最好，覆盖率最难做全 |
| B2 通用协议 + 自定义 URL | 选「正方/强智/青果/URP」→ 填教务 URL → 登录 → 导入 | 协议识别 + 通用解析 | 同协议族全部学校 | 中 | 学校列表缺失时的第一兜底 |
| B3 WebView 登录 + 页面注入 | 打开教务 → 登录 → 点「导入本页」 | 注入 JS 读 DOM/发同源请求 | 几乎所有 Web 教务 | 中（页面改版即失效） | 业界公共解，适合长尾 |
| B4 文件导入 | 教务导出 → 选文件 → 解析 | xls/xlsx/csv/ics/json/html/zip 解析 | 100%（有导出即可） | 中 | 需要格式容错与预览 |
| B5 粘贴文本 | 复制课表文本 → 粘贴 → 识别 | 正则/启发式解析 | 100% | 低 | 适合应急 |
| B6 AI 截图/OCR | 截图/拍照 → 识别 → 预览 | OCR + 结构化抽取 | 100%（有课表页面即可） | 中-高（模型成本/准确率） | 星链等产品的主打卖点 |
| B7 分享口令/二维码 | 同学分享 → 输入口令/扫码 | WakeUp 短码+服务端（有反作弊）；星链分享码第三方可无鉴权 GET 明文 JSON；拾光 GLOBAL_TOOLS 已能导入别家码 | 正在变成跨 App 输入格式 | 低-中 | 短码+服务端是单点；分享码需版本钉死与隐私提示 |
| B8 ICS 日历订阅 | 导出 ics → 导入系统日历 | iCalendar 标准 | 100% | 低 | 适合「不想装 App」的用户 |
| B9 手动录入 | 逐条添加 | 本地表单 | 100% | 低 | 最后兜底 |
| B10 浏览器插件/用户脚本 | 电脑浏览器装脚本 → 导出 | Tampermonkey / 扩展 | 桌面场景 | 中 | 适合极客用户 |
| B11 教务导出 → 转换器 | 上传 zip/xlsx → 下载 ics/csv | 第三方 Web 工具 | 单校/单厂商 | 低 | 如 zf-to-ics、wmukebiao |

**分层结论**：
- **自动化层**：B1 + B2 + B3，覆盖「有 Web 教务且能登录」的绝大多数学校。
- **半自动层**：B4 + B11，覆盖接口被封/页面改版/导出可用的学校。
- **人工层**：B5 + B6 + B9，覆盖一切剩余情况，保证 100% 可用。
- **传播层**：B7 + B8，提升分享与跨端体验。

## 5. 覆盖率测算（按渠道）

> 口径：以 1478 条有协议证据的目录条目为分母；同一条目可能多候选，比例为近似值。

| 渠道 | 可覆盖条目（估算） | 占比 | 说明 |
|---|---:|---:|---|
| A1 JSON 接口直取 | 约 900-1000 | 61%-68% | 正方新版、强智 app.do、金智、新 URP、树维 JSON、超星部分 |
| A2 HTML 表格解析 | 约 500-600 | 34%-41% | 青果、正方旧版、老 URP、树维 classic、乘方、强智 jsxsd 的 HTML 通道 |
| A3 教务导出文件 | 上限约 900，学生端可用率远低 | — | 需用户手动操作，格式一校一样；青果/强智多在教师端，正方每课一个 zip |
| A4 移动端接口 | 与 A1/A2 重叠 | — | 入口不同，数据同源 |
| B3 页面注入 | 约 95%+ | — | 只要有 Web 课表页即可 |
| B4-B9 兜底 | 100% | — | 人工成本换覆盖率 |

**结论**：只做 A1 能覆盖约三分之二；A1+A2 能覆盖九成以上可判协议条目；剩下的一成长尾（单校自建、研究生、IEAS/node 变体、纯 App 教务）必须靠 B3-B9。

**实测口径参照**：Sleepy 350 个有实测证据的导入配置（对应 4140 条目录，转化率约 8.5%）；拾光 269 个 adapter / 264 校；WakeUp APK 内置 3,570 条学校记录，但官方口径只有 1200+/1800+。可见「目录收录 → 实测可用」存在数量级衰减，产品对外口径应把「收录 / 可尝试 / 已实测」三态分开标注。

## 6. 全国大部分学校的实际选择（分层结论）

1. **本科（1365 所）**：正方新版为主，青果、URP、金智、树维次之；大量学校走统一身份认证/门户，接口是 JSON。
2. **高职专科（1554 所）**：强智、青果、超星三家常见；HTML 表格比例更高，移动端/小程序入口更多。
3. **民办/独立学院**：青果、正方新版、强智；系统版本偏旧，导出功能更常见。
4. **研究生（303 条目录）**：博雅、SEP、南软 GMIS、强智研究生平台、校本系统；几乎都需要单独适配。
5. **成人高校（248 所）**：多数没有面向学生的课表查询，或使用省级平台；优先级最低。

## 7. 关键坑与失败模式

| 失败模式 | 触发条件 | 应对 |
|---|---|---|
| 验证码/滑块 | 登录页 | WebView 内由用户手动完成；不做自动识别 |
| SSO 跳转 | 统一身份认证 | WebView 全程接管，不重放登录请求 |
| webvpn 重写 URL | 校外访问 | 先剥离 VPN 壳再识别协议 |
| 学期参数错误 | `xnm/xqm` 编码各校不同 | 从页面读取/让用户选学期/失败重试相邻学期 |
| 页面改版 | HTML 表格/字段变化 | 通用解析 + 置信度评分 + 脱敏快照反馈 |
| 接口加密/签名 | 超星、部分强智 node 变体 | 优先页面注入；不做逆向破解 |
| 研究生系统误判 | 本科适配器套用 | 域名/标题识别，单独提示 |
| 空课表 | 学期未开始/选课未定 | 区分「EmptySemester」与「解析失败」 |
| 反爬/频率限制 | 高频请求 | 仅在用户触发时取数，不做后台轮询 |

## 8. 对本项目的落地建议

### 8.1 渠道优先级

| 批次 | 渠道 | 理由 |
|---|---|---|
| P0 | 正方新版 JSON、强智 HTML+app.do | 合计约 58% 条目，已有实现/脚本基础 |
| P1 | 青果 HTML、正方旧版 HTML、URP 新/老、树维 classic | 再覆盖约 16%，可沉淀通用表格解析器 |
| P2 | 金智 wisedu、超星、乘方、树维 eams5 | 覆盖有但成本高，先做识别+提示 |
| 长尾 | 研究生、单校自建、IEAS/node | 只做 B3 页面注入 + B4 文件 + B9 手动 |

### 8.2 产品结构（三层漏斗）

```
第一层：学校列表 + 账号直连（B1/B2）
   ↓ 失败
第二层：WebView 登录 + 导入本页（B3）+ 通用表格解析（A2）
   ↓ 失败
第三层：文件导入（B4/B11）+ 粘贴文本（B5）+ 截图识别（B6）+ 手动（B9）
```

### 8.3 工程要点

1. **协议识别层**：URL 指纹 + 页面指纹（参考 Sleepy 的两张表），输出协议与置信度，UI 可改。
2. **通用表格解析器**：表头/节次/单元格/周次/rowspan/iframe 五个组件，供多厂商复用。
3. **脚本兜底**：只做「读当前 DOM → 返回 JSON」，内置/签名、白名单域名，禁止远程下发未签名脚本。
4. **失败可诊断**：区分 NeedsLogin / NoPermission / StructureChanged / EmptySemester，保存脱敏 HTML 快照。
5. **样本回归**：每个协议准备 2-3 份脱敏 HTML/JSON 固件做单测。
6. **学校目录**：状态三态（已实现/待验证/待适配）+ 最后验证时间，超一学期未验证自动降级。

### 8.4 合规底线

- 只访问用户本人账号；密码只在 WebView 输入，不落盘、不上传。
- 课表属个人信息，本地处理优先；日志脱敏（去学号/姓名/Cookie）。
- 不做抢课/代刷/绕过验证码；控制请求频率，仅用户触发时取数。
- 教育 App 备案、PIPL 最小必要；开源代码注意 GPL 只读协议、不复制进闭源产品。
