# 01 · 液态玻璃（Liquid Glass）研究报告

采样时点 2026-10-29 ｜ 研究对象 WWDC25 (2025-06-09) 发布的 Liquid Glass，覆盖 iOS 26 / iPadOS 26 / macOS Tahoe 26 / watchOS 26 / tvOS 26 / visionOS 26。

---

## 1. 起源与定位

### 1.1 从哪里来

- Liquid Glass 的视觉与技术血统来自 **visionOS**（Vision Pro 的玻璃材质系统），WWDC25 把它推广为横跨 Apple 全平台的设计语言。
- 这是 Apple **自 iOS 7 扁平化以来最大的一次视觉改版**；同期 Apple 把 OS 版本号统一为年份（iOS 26 而非 iOS 19），暗示"跨端一致性"是这次改版的真正主线。
- 官方定位原文（HIG · Materials）：

> "Liquid Glass forms a distinct functional layer for controls and navigation elements — like tab bars and sidebars — that floats above the content layer, establishing a clear visual hierarchy between functional elements and content."

也就是：它首先是一个**层级工具**，其次才是一个视觉效果。

### 1.2 它想解决什么

| 旧世界的问题 | Liquid Glass 的答案 |
| --- | --- |
| 六个平台六套观感，跨端学习成本高 | 一套材质、一套形状语言、一套动效 |
| 界面元素（导航、控件）与内容抢注意力 | 功能层"浮起"，内容从玻璃底下透出，内容成为主角 |
| 大屏/多任务下控件边界模糊 | 滚动边缘效果 + 透镜折射，让边界始终可辨 |
| 静态毛玻璃在不同背景上时而看不清 | 自适应染色：材质从背景取亮度与颜色，动态维持可读性 |

### 1.3 一句话模型

**玻璃的物理行为 + 控件的交互行为，合成一个动态材质。** 玻璃负责"看起来有厚度、有折射、有高光"，控件负责"被按下时形变、被滚动时收缩、在导航切换时合并分裂"。

## 2. 光学模型（五要素）

Apple 在 WWDC25「Meet Liquid Glass」中给出的核心属性，可以整理为五条相互耦合的机制：

| # | 机制 | 物理隐喻 | 观感表现 | Web 近似手段 |
| --- | --- | --- | --- | --- |
| 1 | **实时渲染与镜面高光**（Real-time rendering / specular highlights） | 玻璃表面反射光源 | 边缘一条亮边，随光源/指针位置变化 | `inset box-shadow` + 跟随指针的 `radial-gradient` 高光 |
| 2 | **边缘透镜折射**（Lensing / light bending） | 光穿过不同折射率的介质，在边缘弯曲 | 背景在玻璃边缘附近被拉伸、挤压、轻微位移 | 位移贴图 + `feDisplacementMap`；或对背景副本做形变 |
| 3 | **自适应染色**（Intelligent color adaptation） | 有色玻璃把环境色带进来 | 浅背景上偏亮、深背景上偏暗，图标颜色随之调整 | 材质层叠 `rgba` 底色 + `backdrop-filter: saturate()` |
| 4 | **上下文形变**（Contextual adaptation / morphing） | 液滴互相吸引、合并、分裂 | 控件在页面切换、模式切换时连续变形，而不是交叉淡入 | 布局动画 + 形变（FLIP / spring）+ 圆角插值 |
| 5 | **层级浮起**（Hierarchy & float） | 玻璃片浮在纸面上 | 内容滚动时从玻璃底下穿过，边缘出现模糊渐隐（scroll edge effect） | 固定层 + 顶部/底部 `mask-image: linear-gradient` 渐隐 |

**关键洞察**：第 2 条（折射）是 Liquid Glass 与 "glassmorphism 毛玻璃"的分界线。只加模糊和半透明，得到的是 2013 年就有的毛玻璃；**在边缘弯曲背景**，才是 Liquid Glass 的辨识特征。

## 3. 设计原则（HIG 原文级规则）

### 3.1 层级：功能层 vs 内容层

- **不要**在内容层使用 Liquid Glass。原文：

> "Don't use Liquid Glass in the content layer. Liquid Glass works best when it provides a clear distinction between interactive elements and content, and including it in the content layer can result in unnecessary complexity and a confusing visual hierarchy."

  内容层的背景、卡片、分隔用**标准材质**（iOS/iPadOS 提供 ultraThin / thin / regular / thick 四档）。
- **例外**：内容层里的**瞬时交互控件**（slider、toggle）在被操作的那一刻可以呈现玻璃外观，用来强调"这是可交互的"。

### 3.2 节制：越少越对

> "Use Liquid Glass effects sparingly. ... Liquid Glass seeks to bring attention to the underlying content, and overusing this material in multiple custom controls can provide a subpar user experience by distracting from that content."

系统组件（TabView、sidebar、toolbar、sheet、popover）**自动获得**该外观；自定义控件才需要手动施加，且只给"最重要的功能元素"。

### 3.3 变体选择：regular 与 clear

| 变体 | 行为 | 适用 | 注意 |
| --- | --- | --- | --- |
| `regular` | 模糊并调整背景亮度以维持前景可读性 | 大多数系统组件；有大量文字的组件：alert、sidebar、popover | 背景可能造成可读性问题时优先用它 |
| `clear` | 高度透明，最大化背景可见性 | 浮在照片/视频等视觉丰富背景上的控件 | 背景偏亮时，考虑在组件后加 **35% 不透明度的深色压暗层**；背景足够暗或使用 AVKit 自带压暗的媒体控件时不需要 |

### 3.4 配色与光照

- 系统颜色会随外观（浅/深）与"增强对比"设置变化；自定义颜色必须同时提供**浅色、深色、增强对比**三种变体，即便 App 只做单一外观也要提供双套色，因为 Liquid Glass 的适应性依赖它。
- 必须**在多种光照条件下实测**（户外强光下颜色显得更深更闷，暗环境下更亮更饱和）；True Tone、P3/sRGB 色域都要覆盖。
- 材质上的文字/图标使用**vibrant（活力）颜色**，不要用普通灰（HIG 明确给了正反例）。

### 3.5 无障碍

- **降低透明度（Reduce Transparency）**、**增强对比（Increase Contrast）** 会改变材质外观；系统设置中的 **Clear / Tinted** 偏好同样会改变外观 —— 三者都必须有回退设计。
- **减弱动态效果（Reduce Motion）**：形变、透镜随动、指针高光应降级为交叉淡入或静态。
- 玻璃材质对 VoiceOver **不需要**任何额外描述，它是装饰性材质，不要把它读成内容。

## 4. 形态语言（组件级）

| 组件 | Liquid Glass 下的形态 |
| --- | --- |
| 标签栏 Tab Bar | 胶囊形浮起；滚动时收起/最小化（minimize behavior），切换分区时形变 |
| 侧边栏 Sidebar（macOS/iPadOS） | `NavigationSplitView` 自动变玻璃；与内容区有明确层级 |
| 工具栏 Toolbar | 玻璃容器 + **滚动边缘效果**：内容滚到边缘时模糊并渐隐，把玻璃与内容分开 |
| 按钮 | `.glass`（中性玻璃胶囊）与 `.glassProminent`（同色系高亮玻璃，用于主操作） |
| Sheet / Popover / Alert | regular 变体为主；多玻璃元素需放进 `GlassEffectContainer` 共享渲染与融合 |
| 图标 | 分层（背景 / 中景 / 前景 + 深度组），由系统实时打光，支持 default / dark / **tinted** / **clear** 四种外观模式 |
| 滑块 / 开关 | 平时普通，操作瞬间玻璃化（唯一的"内容层例外"） |

### 4.1 同心圆角（concentricity）

WWDC25 提出的形状原则：**子元素圆角与其容器圆角同心**，即

```
radius_inner ≈ radius_outer − padding
```

例：卡片圆角 28、内边距 12，则内部按钮圆角取 16。这条规则让你的界面在任何缩放/尺寸类下都不会出现"圆角打架"的廉价感，是 Liquid Glass 观感自然的核心原因之一。

## 5. 时间线与版本演进

| 时间 | 事件 |
| --- | --- |
| 2025-06-09 | WWDC25 主题演讲发布 Liquid Glass；同日开发者测试版上线；发布新版设计库（Sketch/PSD/AI）与 SF Symbols 7、Icon Composer |
| 2025 夏 | 测试版反馈集中爆发：可读性、性能、耗电、"看起来廉价"；Apple 在多轮 beta 中提高不透明度、收敛透明观感 |
| 2025-09 | iOS 26 正式版随 iPhone 17 发布 |
| 2025-10-20 | iOS/iPadOS 26.1 beta 4 新增 **Settings > Display & Brightness > Liquid Glass > Clear / Tinted**（macOS 在 System Settings > Appearance）。Apple 的说法是：夏季测试期用户反馈希望有更不透明的选项。Tinted 提高不透明度并增加对比，作用于全系统（含锁屏通知），浅色与深色模式下表现不同 |
| 2026-10（当前） | Liquid Glass 已在 26.x 线上稳定运行；后续 OS 迭代继续围绕"可读性 + 可定制"微调 |

**这条时间线的意义**：Apple 自己也在"玻璃感"与"可读性"之间来回校准，并且在 26.1 把最终裁量权交回用户。任何复刻或引入 Liquid Glass 的项目，都应该把 **Clear / Tinted 双形态**当成一等需求，而不是可选项。

## 6. 争议与工程结论

### 6.1 三类主要批评

1. **可读性**：文字与图标叠在透明材质上，在复杂背景/强光下对比不足；大批用户称其为"iOS 7 以来最丑的一次改版"。
2. **性能与续航**：实时模糊、折射、形变持续占用 GPU，旧机型压力大。
3. **设计同质化**：所有 App 长得一样，品牌识别被削弱。

### 6.2 工程结论（可直接执行）

- **可读性**：所有玻璃承载的文字用"最坏背景"校验对比，正文目标 4.5:1、大字 3:1；做不到就加压暗层（35% 深色，HIG 给的就是这个数）或换 regular 变体。
- **性能**：玻璃元素数量设上限（一屏建议不超过 3–5 个独立玻璃层）；不在滚动列表的每一行上做玻璃；Web 端位移滤镜只作用于小面积装饰层。
- **品牌**：把品牌表达放在**内容层**（配色、排版、图形），玻璃只承担功能层；这正是 HIG 的层级原则，也顺手解决了同质化指责。
- **可定制**：同时交付 Clear 与 Tinted 两套观感，并接入系统的降低透明度/增强对比开关。
- **什么场景不适合**：文字密集的阅读界面、数据密度高的表格/仪表盘、低端设备为主的用户群、需要强品牌差异化的首屏。
