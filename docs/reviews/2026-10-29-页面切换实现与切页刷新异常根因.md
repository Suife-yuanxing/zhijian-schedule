## 二、「切页刷新异常 / 从左上角打开」的根因

### 已确证主因：课表根页每次进入都无条件重播入场级联

调用链（全部真实代码路径）：
```
底栏点击 课表 (AppRoot.kt:234-243)
  → navigateToTab(SCHEDULE_TAB) (AppTransitions.kt:163-169)
    → currentBackStackEntryAsState 变 (AppRoot.kt:137)
      → LaunchedEffect(backStackEntry) (AppRoot.kt:145)
        → navState.onScheduleShown() (AppNavHostState.kt:74-76)  // epoch++
          → ScheduleScreen(entryEpoch = ...) (AppNavGraph.kt:176)
            → WeekGrid(entranceEpoch = ...) (ScheduleScreen.kt:157)
              → CourseOverlay → CourseCell → CourseBlock(entranceKey = entranceEpoch) (WeekCourseOverlay.kt:152)
                → cascadeIn 换新 Animatable(0f) (MotionModifiers.kt:178-180)  // 全部课块 alpha 归 0
                  → LaunchedEffect 延迟后 animateTo(1f) (MotionModifiers.kt:181-188)
```

**真机抓帧证据**（`.tmp/frames/v_*.png`，点击课表后按延时截屏）：

| 延时 | 观测 |
|---|---|
| 30ms | 页面滑入中，课块**全部不可见**（底色 + 网格线） |
| 90ms | 第 1、2、5 节列依次出现淡淡的块 |
| 300ms | 周一/周四已实，周三「习近平新时代…」仍是半透明 |
| 500ms | 周三块实，周四「包装插画设计」仍偏淡 |
| 800ms | 全部落位 |

这正是 `WeekCourseOverlay.kt:26-40` 设计出来的「阅读顺序 + 每块 70ms、整轮封顶 700ms」——**用户看到的「页面刷新」就是这 700ms**。

**「从左上角打开」的几何来源**（三处叠加）：
1. 顺序是阅读顺序：`WeekCourseOverlay.kt:63-65` `sortedWith(compareBy({ startSection }, { colIndex }))` → 先上排、上排内从左到右 → 视觉锚点天然落在**左上**。
2. `StaggerIn` 的容器不撑宽：`MotionModifiers.kt:143-152` 的 `Box` 只有 `modifier`（调用点均未传 `fillMaxWidth`），父 `Column` 默认 `horizontalAlignment = Start` → 子项左对齐、宽度=内容宽 → alpha<1 时离屏层也只有内容那么大，读起来是「从左上角一块块长出来」，而不是整页一起亮。
3. `cascadeIn` 还叠了 `scale = 0.78 → 1`（`MotionModifiers.kt:175,192-194`）+ `translationY = 10dp → 0`（195）→ 每块从左上往右下「弹开」。

**为什么只有根页**：今日/我的都有闸门（见上表），**只有课表没有**。二级页（编辑/导入/成绩/设置/考试）根本不参与这套级联，所以不触发。

### 已确证次因：快速切页时级联被打断后从 0 重来（偶发的来源）

- `AppNavHostState.kt:34-46` 与 `MotionModifiers.kt:159-170` 都写明了同一件事：navigation-compose 转场按 back stack entry 的 **id** 复用内容槽，`saveState/restoreState` 恢复的 entry 还是同一个 id → 「转场收尾前切回来」时页面**没离开组合**，`remember` 不重跑 → 级联**不重播**。这就是「慢切有、快切没有」。
- 反向：切走够久页面真被销毁 → 再回来 epoch 又变 → `remember(restartKey)` 换新 `Animatable(0f)` → 正在播到 0.6 的 alpha **瞬间跳回 0** 再重播 → 视觉上是「闪一下，然后重新长」。
- `AppTransitions.kt:62-66` 已记录过打断态的另一种残留：tab 转场带 `scaleIn/scaleOut`，被打断后 alpha 可能停在 ~0.1（幽灵帧）。

所以「偶发」= **重播一次**（看得见）vs **没重播**（看不见，因为页面留在组合里）两种结果取决于上一段转场有没有收尾，而收尾时机取决于帧率/是否连点——不是稳定可复现的。

### 连带问题（同一条链上，建议一并处理）

1. **从编辑页返回课表也会重播级联**：pop 回 `Routes.SCHEDULE` 同样是目的地变化 → `AppRoot.kt:145-147` 自增 → 级联重播。`RevealHost.kt:151-158` 的注释已经踩过一次这个坑（反向收回时抓到的课表「半空」，动画结束硬切一下）。
2. **空态卡片每轮都换实例**：`ScheduleScreen.kt:128` `key(entryEpoch){ StaggerIn(...) }` → 整棵子树销毁重建，比单纯重播更重。
3. **加号也重弹**：`ScheduleFab.kt:46-49` `snapTo(0f) → animateTo(1f)`，与课块同拍，进一步强化「整页刷新」的观感。
4. **潜在次生 bug（未触发）**：`RevealState.hostSize` 初值 `IntSize.Zero`（`RevealState.kt:148`），`revealRadius` 此时返回 0（`RevealMath.kt:40-44`）→ 若在宿主首帧前发起页面扩散，圆半径为 0 会表现为「瞬切」。目前调用点都晚于布局，未暴露。

### 误判排除（都已核对，不是原因）

| 候选 | 结论 | 依据 |
|---|---|---|
| NavHost `contentAlignment = TopStart` 导致整页从左上角缩放 | **排除** | 字节码确认默认值确为 `Alignment.Companion.getTopStart()`（`navigation-compose-release.aar` → `NavHostKt.class`），但三根页根容器都是 `fillMaxSize`（`TodayScreen.kt:91-93`、`ScheduleScreen.kt:97`、`ProfileScreen.kt:104-106`），`SizeTransform` 没有尺寸差可动 |
| `scaleIn/scaleOut` 的 pivot | **排除** | 默认 `TransformOrigin.Center`；且只缩 0.98/0.99，肉眼几乎不可见 |
| RevealHost 圆形裁剪 | **排除** | `RevealHost.kt:117-137` 只在 `state.active != null` 时裁剪；切 tab 不发起 reveal |
| 玻璃折射图层 | **排除** | `GlassBackdrop.kt:70-84` `enabled = showBottomBar`，只影响浮岛采样；当前主题是纸感（`preset.glass == null`），`rememberGlassBackdrop` 直接返回 null（51-52） |
| ViewModel 被重建 | **排除** | `popUpTo(graph.id){saveState=true}` 会保存 ViewModelStore，切回不重建；`ScheduleViewModel.uiState` 是 `WhileSubscribed`，5s 内切回连流都不断 |
| `rememberSaveable` 回退导致 `playEntrance` 复位 | **排除**（我的页） | `ProfileScreen.kt:94` 的 `animatedEpoch` 用 `rememberSaveable`，进程内稳定 |

## 三、最小改动修复

### 方案 A（推荐，改动 2 个文件）：给课表补上与今日/我的一致的闸门

`app/src/main/java/com/zhijian/schedule/navigation/AppNavHostState.kt`
```diff
+    /** 课表分段/课块级联是否已播过：与「我的」同一策略，进程内一次 */
+    private var scheduleEntrancePlayed by mutableStateOf(false)
+
+    /** 上方有课表要进场时调用：本次进程只放行一次级联 */
+    fun playScheduleEntranceOnce() {
+        if (!scheduleEntrancePlayed) {
+            scheduleEntrancePlayed = true
+            onScheduleShown()
+        }
+    }
```

`app/src/main/java/com/zhijian/schedule/navigation/AppRoot.kt:145-147`
```diff
     LaunchedEffect(backStackEntry) {
-        if (backStackEntry?.destination?.route == Routes.SCHEDULE) navState.onScheduleShown()
+        if (backStackEntry?.id != null && backStackEntry.destination.route == Routes.SCHEDULE) {
+            navState.playScheduleEntranceOnce()
+        }
     }
```

> 注意：这一改会让「每次进课表都摊开一次」变成「进程内只摊开一次」。CHANGELOG:138 写的是「级联入场只播一次」，但代码里课表刻意不做闸门（`AppNavHostState.kt:51-58` 注释说明「课表按需求每次进入都重播」）。**这条改动的产品口径需要主人拍板**：要「只播一次」选 A；要「保留每次重播但消除刷新观感」选 B。

### 方案 B（保留每次重播，但让它不像「刷新」）

1. `MotionModifiers.kt:143-152` 给 `StaggerIn` 的 Box 补 `fillMaxWidth()`，并显式 `transformOrigin = TransformOrigin.Center`：
```diff
     Box(
         modifier
+            .fillMaxWidth()
             .graphicsLayer {
+                transformOrigin = TransformOrigin.Center
                 alpha = progress
                 translationY = (1f - progress) * 20.dp.toPx()
             }
```
2. `MotionModifiers.kt:189-196` 的 `cascadeIn` 同样补 `transformOrigin = TransformOrigin.Center`（去掉「从左上角弹开」的观感）。
3. `WeekCourseOverlay.kt:35-36` 把整轮上限 `ENTER_TOTAL_CAP_MS` 从 700 压到约 320（等于切页滑动 230ms 的量级），让重播不再读成「页面刷新」。
4. `ScheduleScreen.kt:128` 去掉 `key(entryEpoch)`，改成 `StaggerIn(index = 0, skip = entryEpoch == 0)`，避免整棵空态子树重建。

### 方案 C（消掉「偶发」本身）：打断保护

`MotionModifiers.kt:178-188`，把「换新实例 → 归 0」改成「已在途中就接着走」：
```diff
-    val progress = remember(restartKey) { Animatable(if (delayMs < 0) 1f else 0f) }
-    LaunchedEffect(restartKey, delayMs) {
-        if (delayMs < 0) { progress.snapTo(1f) }
-        else { delay(delayMs); progress.animateTo(1f, Motion.CascadeEnter) }
-    }
+    val progress = remember { Animatable(if (delayMs < 0) 1f else 0f) }
+    LaunchedEffect(restartKey, delayMs) {
+        when {
+            delayMs < 0 -> progress.snapTo(1f)
+            // 已经在位（上一轮播完）→ 重播；被打断在半路 → 接着走完，不归 0
+            progress.value >= 1f -> { progress.snapTo(0f); delay(delayMs); progress.animateTo(1f, Motion.CascadeEnter) }
+            else -> progress.animateTo(1f, Motion.CascadeEnter)
+        }
+    }
```
> 这会改掉「每轮都从头摊开」的既定观感，需要确认是否接受。

## 四、复现与验证

### 复现（已实测可用）
```bash
# 1) 慢切（必现「刷新」）：坐稳在今日 → 点课表 → 立刻连拍
adb exec-out "input tap 120 2200; sleep 0.9; input tap 540 2200; sleep 0.30; screencap -p" > f300.png
# 2) 快切（偶发「不刷新」）：两次点击间隔 < 一次转场收尾（约 230ms）
adb shell input tap 120 2200; sleep 0.15; adb shell input tap 540 2200
# 3) 打断重播（必现「闪一下重长」）：切到课表中途切走再切回
adb shell input tap 540 2200; sleep 0.12; adb shell input tap 950 2200; sleep 0.12; adb shell input tap 540 2200
```
