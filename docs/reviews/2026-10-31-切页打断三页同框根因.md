# 根页切换偶发「画面从左上角打开」根因：AnimatedContent 转场被二次导航打断

- 日期：2026-10-31
- 环境：PKG110 / Android 16 / ColorOS，release v1.0.15（含 27d28ec 入场闸门修复）
- 结论：**底栏切页的转场（约 220ms 弹簧）进行中被第二次切页导航打断时，NavHost 内部的
  AnimatedContent 走打断路径，产出「三页同框 + 页间缝隙 + 目的地迟到落位」的病灶帧**。
  backward 方向（课表→今日）时目的地从左侧迟到滑入，读作「画面从左上角打开」。
  1x 速度下对应两次点不同 tab 间隔约 120–250ms 的日常误触，故表现「偶发」。

## 为什么历次修复都没除根

| 修复 | 治的伪影 | 为何对本病灶无效 |
| --- | --- | --- |
| d90d36c 等距滑动 + 去 alpha | 左缘硬切、alpha 幽灵帧（单次转场内部） | 打断路径根本没被触及 |
| d4a09c5 / 27d28ec 入场闸门 | 切 tab 重播级联（目的地从左上长出） | 闸门后单次转场已干净，但打断是另一条路径 |
| 本次的等距/零 alpha 约束 | 同上 | 病灶帧里两页距离既不等、速度也不连续 |

三次修复都默认「一次转场是原子的」，而 AnimatedContent 的打断行为破坏了这个前提。

## 病灶帧证据（10x 慢放 + 截图连拍，`animator_duration_scale=10`）

`docs/reviews/2026-10-31-病灶帧-三页同框-修复前.png`（序列第 3 帧，`sheet_b3` 全序列同目录）：

「我的 → 课表 → 今日」三次点击、间隔 ~1.2s（10x 下等于在转场 55% 处重定向）后抓到：

- **三个页面同框**：「今日」页只露出右侧一角（弹簧从错误相位重启、约 -580px 停在中途）、
  「课表」页是一条 ~350px 窄带、「我的」页残影还挂在最右缘——按语义「我的」页应在
  重定向那一刻被 AnimatedContent 摘除；
- 「今日」与「课表」页边缘之间有 **~20px 缝隙**露出底色；
- 后续帧显示弹簧收尾被拖长，目的地迟到最后才滑回原位。

同类已知问题：Google Issue Tracker「AnimatedContent sets incorrect target animation on
interrupt」（238662479）。Compose BOM 2026.03.01 / navigation 2.9.5 上仍可复现，升级不可行。

## 修复：切页单飞队列（TabSwitchQueue）

`navigation/TabSwitchQueue.kt`（单测 `TabSwitchQueueTest`，6 例）：

- 底栏点击不再直接 `navigateToTab`，改投 **conflated channel**：落位窗口内的连点
  只保留最后一次意图；
- worker 保证**任意两次导航间隔 ≥ 落位窗口**（`TAB_SWITCH_SETTLE_BUDGET_MS = 260ms`，
  即 SlideSpring 约 220ms 落位 + 40ms 余量），窗口在源头就消除了「打断」这个状态本身；
- 窗口预算**按系统「动画时长」缩放折算**（`animatorScaledBudgetMs`）：10x 慢放下转场
  真的要 2.2s，固定 260ms 会在调过开发者选项的设备上失效；缩放为 0（关动画）时预算为 0；
- 语义代价：误触后立刻改点的第二次切页，会在上一次转场落位后执行——一次干净转场
  替换原来的坏帧。点击反馈（弹跳、浮岛展开）不受影响，仍立即发生。

通知/胶囊跳转（openTodayCount / openJwImportCount）不排队：它们发生在进程刚启动、
无转场在跑的时刻。

## 复验

同一协议（10x 慢放 + 连拍 22 帧，覆盖「我的→课表→今日」三段连续转场）：

- 修复后每一帧都是**恰好两页等边相接**，无第三页残影、无缝隙（`2026-10-31-修复后帧序列.png`）；
- 排队的两次导航在窗口后依次干净执行（三段背靠背滑动）；
- 1x 常规切页回归正常；
- JVM 单测 6 例全绿（含「同帧三连点合并为最后一次」「排队导航重新计时」「预算逐次重估」）。
